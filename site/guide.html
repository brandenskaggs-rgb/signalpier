Install on Windows 10/11.

Download the Windows .exe from the Downloads page, open it, and follow setup. Launch SignalPier from the Start menu. Python is included. The app runs under your user account and opens its local dashboard in your browser.

Connect an RTL-SDR on Windows.

Connect the dongle and antenna, then use Receiver connection → Test connection. If Windows has the TV driver or no suitable USB driver, use the official Zadig tool. Choose Options → List All Devices, select your RTL-SDR receiver’s Bulk-In Interface 0, and install WinUSB for that interface. Check the device is your SDR before changing its driver. Reconnect it, close other SDR apps, and refresh SignalPier’s device list.

Download. Allow execution. Open.

On your Pi, download the AppImage. Right-click the file, choose Properties → Permissions, and allow execution as a program. Double-click it to open SignalPier. The receiver tools are included; you do not install a package or unpack source code.

Terminal equivalent, from your Downloads folder:

chmod +x SignalPier-0.1.0-alpha.4-aarch64.AppImage
./SignalPier-0.1.0-alpha.4-aarch64.AppImage

Open your radio desk.

The AppImage starts your local radio service and opens its browser dashboard. First launch adds a SignalPier shortcut to your applications menu. Use that shortcut next time. Choose Quit SignalPier in the dashboard to stop the app.

Your user-owned app is stored in ~/.local/share/signalpier/SignalPier.AppImage. Launching needs no administrator password. If USB receiver access is denied, Settings → Enable USB receiver access opens a one-time administrator prompt; then reconnect the SDR.

Use a laptop screen or headless Pi

Start the AppImage with --no-browser on the Pi. On your laptop, keep this command running:

ssh -N -L 8765:127.0.0.1:8765 YOUR_USER@YOUR_PI

Open http://127.0.0.1:8765 on your laptop. If another program occupies port 8765, SignalPier selects a free port and prints it; use that port instead.

Offline use and updates.

Reception, the station clock, demo mode and encryption lab work offline. When internet is available, SignalPier checks this website for a new version. An Update available pop-up appears when a new version is found. Choose Install update or Later. In Windows, installation closes and reopens the app; in the Pi AppImage, the update replaces the installed app file. On Pi, quit and reopen from the application-menu shortcut when the update finishes. Settings → Check for updates performs an immediate check. Updates do not install until you click.

Connect your SDR.

  1. Connect a supported RTL-SDR USB receiver and an appropriate antenna to the Pi.
  2. Stop any other program using the same dongle. SignalPier lists connected RTL-SDRs by name and serial number.
  3. On the Spectrum tab, select your receiver and click Test connection. Resolve any permission or busy-device message, then choose Hardware and start a short capture.
  4. For compatible weather sensors and supported device protocols, choose packet decoding and enter the device frequency.

Hardware mode invokes actual rtl_power and rtl_433 receiver tools. Demo mode is separately labeled. Not every signal has a supported decoder; this release does not implement P25 voice decoding or encrypted over-the-air messaging.

RTL-SDR Blog V3 is receive-only. This alpha does not transmit or program handheld/mobile radios.

The bundled driver supports standard RTL2832U receivers including RTL-SDR Blog V3. Blog V4 needs a newer driver and is not supported by this AppImage release.

Compatibility and test status.

Primary target: Raspberry Pi 3 Model B / B+, 1 GB RAM, Raspberry Pi OS 64-bit with Python 3.10 or newer. 32-bit Pi OS cannot run the ARM64 AppImage. Pi 4/5 are secondary targets; the original C.H.I.P. is unsupported.

The AppImage launcher and bundled receiver tools are tested in ARM64 userspace under emulation. The actual ARM64 rtl_433 decoder successfully decoded a recorded Acurite sensor sample. Desktop and mobile browser tests cover the interface.

This is an alpha release. Physical Pi 3 reception, thermal behavior, power stability, and performance with your particular receiver still need hardware acceptance. No simulated capture is presented as live reception.

Resource controls: one receiver task at a time, bounded captures, 30 plotted sweeps with at most 1,024 points each, compact status polling, with a 256 MB service memory limit in the optional Debian service installation. These are configured limits, not measured Pi performance claims.

Useful answers.

Do I need to install an operating system?

No. Install this application on your existing supported 64-bit Raspberry Pi OS.

Does it read real radio signals?

Yes, through a supported SDR and antenna in Hardware mode. The spectrum tool measures received energy; rtl_433 decodes supported sensor/device protocols. Receiving and decoding are different operations.

Does the Pi need a screen?

No. Use the laptop connection above. A desktop Pi can open the dashboard directly.

Can it encrypt my radio channels?

The included lab encrypts your own text locally with AES-256-GCM. It does not configure a radio's encryption or transmit messages. Those require a separate compatible radio integration.

How do I troubleshoot or uninstall?

Launch the AppImage from a terminal to see errors. If FUSE is unavailable, run it with --appimage-extract-and-run. To remove it, quit SignalPier and delete its file from ~/.local/share/signalpier and the shortcut ~/.local/share/applications/signalpier.desktop. Report issues with your Pi, OS and receiver model, excluding private data.
