GET STARTED / A REGULAR PI APP

Make it your station.

SignalPier runs on your existing 64-bit Raspberry Pi OS. No SD-card flashing or operating-system replacement.

Download and install.

On the Pi, download SignalPier. Open the downloaded .deb file with the system's software installer and approve the installation. An internet connection is needed to install any missing receiver packages.

If your desktop doesn't provide a graphical .deb installer, open a terminal in the Downloads folder and run:

sudo apt install ./signalpier_0.1.0~alpha1_arm64.deb

Open your radio desk.

Launch SignalPier from the application menu. It opens your browser at http://127.0.0.1:8765. You can also enter that address yourself. The background service starts automatically after installation and at boot.

The four sections are Spectrum, Station clock, Encryption lab, and Settings. Try a demo capture to learn the controls, or connect a receiver and select Hardware.

Use a laptop as the Pi's screen

Keep this command running on your laptop, substituting your Pi username and hostname:

ssh -N -L 8765:127.0.0.1:8765 YOUR_USER@YOUR_PI

Then open http://127.0.0.1:8765 on the laptop. The Pi performs reception; the laptop renders the dashboard.

Offline use and updates.

After installation, reception, the station clock, demo mode and encryption lab work offline. When internet is available, SignalPier checks this website for a newer release and shows an update notice. Click Install update to download and install it; nothing installs automatically. The dashboard reconnects after installation. Online NOAA readings require internet.

Connect your SDR.

  1. Connect a supported RTL-SDR USB receiver and an appropriate antenna to the Pi.
  2. Stop any other program using the same dongle.
  3. Choose Hardware on the Spectrum tab, use receiver index 0 for the first receiver, and start a short capture.
  4. For compatible weather sensors and supported device protocols, choose packet decoding and enter the device frequency.

Hardware mode invokes actual rtl_power and rtl_433 receiver tools. Demo mode is separately labeled. Not every signal has a supported decoder; this release does not implement P25 voice decoding or encrypted over-the-air messaging.

RTL-SDR Blog V3 is receive-only. This alpha does not transmit or program handheld/mobile radios.

Receiver support depends on the installed driver. Standard RTL2832U dongles are the initial target. RTL-SDR Blog V4 requires a sufficiently recent compatible driver, which older distribution packages may not include.

Compatibility and test status.

Primary target: Raspberry Pi 3 Model B / B+, 1 GB RAM, Raspberry Pi OS 64-bit with Python 3.10 or newer. 32-bit Pi OS cannot install the ARM64 package. Pi 4/5 are secondary targets; the original C.H.I.P. is unsupported.

The application and package are tested in an ARM64 environment under emulation. The actual ARM64 rtl_433 decoder successfully decoded a recorded Acurite sensor sample. Desktop and mobile browser tests cover the interface.

This is an alpha release. Physical Pi 3 reception, thermal behavior, power stability, and performance with your particular receiver still need hardware acceptance. No simulated capture is presented as live reception.

Resource controls: one receiver task at a time, bounded captures, 30 plotted sweeps with at most 1,024 points each, compact status polling, and a 256 MB service memory limit. These are configured limits, not measured Pi performance claims.

Useful answers.

Do I need to install an operating system?

No. Install this application on your existing supported 64-bit Raspberry Pi OS.

Does it read real radio signals?

Yes, through a supported SDR and antenna in Hardware mode. The spectrum tool measures received energy; rtl_433 decodes supported sensor/device protocols. Receiving and decoding are different operations.

Does the Pi need a screen?

No. Use the laptop connection above. A desktop Pi can open the dashboard directly.

Can it encrypt my radio channels?

The included lab encrypts your own text locally with AES-256-GCM. It does not configure a radio's encryption or transmit messages. Those require a separate compatible radio integration.

How do I troubleshoot or uninstall?

Check systemctl status signalpier and journalctl -u signalpier -n 50 --no-pager. Uninstall with sudo apt remove signalpier. Report issues with your Pi, OS and receiver model, excluding private data.
